## Why this matters

`npm audit` reports **HIGH** severity vulnerabilities in the currently installed
Next.js 16.2.4, including:

- Denial of Service via Server Components and Image Optimization API
- Middleware / Proxy bypass (segment-prefetch routes — two separate CVEs, one
  incomplete fix followed by a follow-up)
- Cache poisoning in RSC responses and React Server Component cache-busting
- Cross-site scripting in CSP nonces and `beforeInteractive` scripts
- SSRF in applications using WebSocket upgrades
- Dynamic-route parameter injection for middleware bypass

The `latest` dist-tag for the `16.x` line as of plan-writing is **16.2.9**.
Upgrading from 16.2.4 → 16.2.9 is a five-patch bump within the same minor and
resolves all of the above CVEs.

## Steps

### Step 1: Upgrade Next.js

```bash
npm install next@16.2.9
```

Confirm `package.json` now contains `"next": "16.2.9"` (exact, not a range).

**Verify**: `npm list next` → prints `next@16.2.9`

### Step 2: Typecheck

```bash
npx tsc --noEmit
```

Expected: exit 0, no output. A patch upgrade should not introduce new type
errors. If there are errors, read them carefully — if they mention internal
Next.js types that changed, that is a STOP condition (the release has a
regression); if they are in application code, fix them.

### Step 3: Run tests

```bash
npm test
```

Expected: all pass. Tests do not invoke Next.js internals directly, so
failures here would be an indirect signal of a bad upgrade.

### Step 4: Confirm audit is clean for Next.js

```bash
npm audit --audit-level=high 2>&1 | grep -E "next|high|critical"
```

Expected: no line that attributes a HIGH or CRITICAL finding to `next`.
(Other HIGH findings from `minimatch`/`mocha`/`paperclip` are acceptable here
— they are dev-only and out of scope.)

### Step 5: Build

```bash
npm run build
```

Expected: exits 0. Check that the build output mentions `16.2.9`:

```bash
node -e "console.log(require('./node_modules/next/package.json').version)"
```

Expected: `16.2.9`

### Step 6: Smoke test (manual, ~5 min)

Start the dev server (`npm run dev`) and verify:

1. `/` — dashboard loads, deck grid renders
2. `/quiz/quick` — quick quiz starts
3. `/quiz/<any-deck-id>` — deck quiz starts, cards load
4. Any page with a logged-out state — confirm no unexpected 500s

### Step 7: Commit

```bash
git add package.json package-lock.json
git commit -m "fix(deps): upgrade next.js 16.2.4 → 16.2.9 (security patch)"
```

No new tests needed — this is a dependency version bump. The verification gate

## STOP conditions

- `npx tsc --noEmit` produces errors referencing Next.js internal types —
  indicates a regression in the release; do not attempt to patch application
  code to work around it; report back
- `npm run build` fails with an error that does not appear in 16.2.4 — same;
  report back
- Any application code changes are required to make the upgrade compile — that
  would indicate this is not a safe patch bump; stop and report
